# Enemy Spell Cast 設計仕様

## 1. 目的

Enemy Spell Cast は、Minecraft 1.21.1 / NeoForge 向けの L2 Hostility アドオンである。L2 Hostility の特性を得た敵対 Mob が、Iron's Spells 'n Spellbooks の魔法を状況に応じて詠唱する。

本 MOD の目的は、敵が多く出現する MOD パックに、個体ごとの予測不能な魔法構成と、L2 Hostility の難易度進行に連動した脅威を加えることである。既存 Mob の通常攻撃 AI は維持し、魔法は追加の戦闘手段として機能させる。

## 2. 対象環境

- Minecraft: 1.21.1
- Mod Loader: NeoForge 21.1 系
- Java: 21
- 必須 MOD:
  - L2 Hostility 3.0.18 互換系列
  - Iron's Spells 'n Spellbooks 1.21.1-3.16 系
  - 上記 MOD が要求する依存 MOD
- MOD 名: `Enemy Spell Cast`
- MOD ID: `enemyspellcast`

## 3. スコープ

### 3.1 含むもの

- L2 Hostility の新規特性「Spell Caster / 魔導」
- 特性 Mob 固有の魔法ロードアウト
- 最大3種類の魔法
- L2 Mob レベルによる魔法性能強化
- 特性ランクによる魔法数、レアリティ、魔法レベルの解禁
- 状況判断とランダム性を併用する魔法 AI
- マナ、クールタイム、詠唱、中断
- 攻撃魔法の同士討ち防止
- 回復・バフ魔法による敵側 Mob の支援
- サーバー config、データパック、Entity Type タグによる調整
- 英語および日本語翻訳
- L2 Hostility 上で表示する特性アイコン

### 3.2 初期リリースに含まないもの

- プレイヤー用の新規魔法、装備、アイテム
- 一般 Mob への専用人型詠唱アニメーションの強制
- 安全性を確認できない継続詠唱魔法
- 地形破壊、特殊なプレイヤー操作、または不安定な所有者処理を必要とする魔法
- クライアント専用の設定画面

## 4. 基本ゲームデザイン

### 4.1 特性

特性 ID は `enemyspellcast:spell_caster` とし、最大ランクは5とする。自然生成は L2 Hostility 標準の特性抽選へ統合する。

初期データパック値:

- `min_level`: 100
- `cost`: 80
- `weight`: 30
- `max_rank`: 5

これらの値は L2 Hostility のデータパック機構で変更できる。Mob レベル100未満では自然付与されないが、管理コマンド等による手動付与は妨げない。

自然生成時の特性ランクは L2 Hostility 標準のポイント消費とランダム抽選へ従う。同じ Mob が時間経過で自然にランクアップするのではなく、生成時点の Mob レベル、他特性に消費されたポイント、L2 Hostility 全体の特性ランク上限から決定する。

`cost = 80` で、他特性にポイントを消費していない場合の目安は以下とする。

| L2 Mob レベル | 抽選され得る特性ランク |
| ---: | --- |
| 100～159 | 1 |
| 160～239 | 1～2 |
| 240～319 | 1～3 |
| 320～399 | 1～4 |
| 400以上 | 1～5 |

Lv.400前後からランク5が出現可能になるが、ランク5を保証しない。他特性が先にポイントを消費した個体では、より高い Mob レベルでも低ランクになり得る。特性の `weight` は本特性自体が選ばれる確率へ影響し、選択後のランクを直接固定しない。

### 4.2 対象 Mob

L2 Hostility が特性を付与できる敵対 Mob を原則として対象とする。以下は初期状態で除外する。

- ボス
- 召喚 Mob
- Iron's Spells 側ですでに魔法 AI を持つ Mob
- 明示的な除外 Entity Type タグに含まれる Mob

除外対象は Entity Type タグおよび config で追加・解除できる。除外 Mob は本特性を自然生成候補に含めない。既に手動付与された場合も、初期設定では魔法 AI を起動しない。

### 4.3 魔法数、レアリティ、レベル

| 特性ランク | 魔法数 | 抽選可能な最大レアリティ |
| ---: | ---: | --- |
| 1 | 1 | Common |
| 2 | 1 | Uncommon |
| 3 | 2 | Rare |
| 4 | 2 | Epic |
| 5 | 3 | Legendary |

最大レアリティ以下の全候補から、重複なしの加重抽選を行う。攻撃・回復・補助などの役割構成は保証せず、すべてのスロットを同一候補集合からランダムに選ぶ。

使用魔法レベルは次式で求める。

```text
spellLevel = 1 + floor((spellMaxLevel - 1) * (traitRank - 1) / 4)
```

このため、特性ランク1は最低魔法レベル、ランク5は魔法本来の最大レベルを使用する。

### 4.4 ロードアウトの永続性

魔法ロードアウトは特性付与後の初回評価時に生成し、Mob の永続データへ保存する。チャンクのアンロード、サーバー再起動、ディメンション移動後も同じロードアウトを維持する。

特性ランクが上昇した場合は既存魔法を維持し、不足スロットだけを追加抽選する。ランク低下時は先頭から許容数だけを有効にし、保存済みの余剰魔法は再上昇に備えて保持してよい。削除済みまたは無効化された魔法は候補から除去し、不足分を安全に再抽選する。

自然生成後の通常プレイでは特性ランクは自動成長しない。ここでいうランク上昇・低下は、管理コマンド、L2 Hostility側の機能、または他MOD連携によって既存個体の特性ランクが変更された場合を指す。

## 5. レベルスケーリング

Mob レベル100を基準とし、初期状態では50レベルごとに1段階強化する。

```text
tier = floor(max(0, mobLevel - 100) / 50)

spellPowerMultiplier = 1.0 + tier * 0.10
maxMana             = 100 + tier * 20
manaRegenMultiplier = 1.0 + tier * 0.05
castSpeedMultiplier = min(3.0, 1.0 + tier * 0.05)
cooldownMultiplier  = max(0.25, 1.0 - tier * 0.05)
```

- 魔法威力、最大マナ、マナ回復速度は段階的に上昇し、上限を設けない。
- 詠唱速度は基準の3倍を上限とする。
- クールタイムは基準値の25%を下限とする。
- 段階幅、各増加量、詠唱速度上限、クールタイム下限はすべてサーバー config で変更できる。
- 実際の魔法コストと基礎クールタイムは Iron's Spells の定義を尊重する。

## 6. アーキテクチャ

### 6.1 `SpellCasterTrait`

L2 Hostility に登録する特性クラス。最大ランク、表示情報、自然生成条件、および特性 Mob の起動判定を提供する。L2 Hostility の既存特性ライフサイクルへ従い、独自の全 Mob 走査は行わない。

### 6.2 `SpellCasterData`

特性 Mob にのみ作成するシリアライズ可能なデータ。

保存対象:

- 抽選済み魔法 ID の順序付き一覧
- 現在マナ
- 魔法ごとの残りクールタイム
- データ形式バージョン

一時的な詠唱対象や AI スコアは保存しない。読み込み時に存在しない魔法 ID は破棄し、不足分を再抽選する。

### 6.3 `SpellCasterGoal`

一般 Mob に追加する独自 AI Goal。Iron's Spells の `IMagicEntity` を他 MOD Mobへ Mixin 注入しない。

責務:

- 判断間隔の管理
- 使用可能魔法の評価
- 攻撃対象または支援対象の選定
- 射程、射線、マナ、クールタイムの検査
- 詠唱開始、視線、移動抑制、予告演出
- ダメージによる詠唱中断
- Iron's Spells の魔法ライフサイクル呼び出し
- 成功後のマナ消費とクールタイム設定

AI Goal は元の近接・遠距離 AI を削除しない。魔法を使用できないときは制御を返し、通常行動を継続させる。Goal の多重登録を防ぎ、特性削除後は `canUse` を失敗させて休止する。

### 6.4 `SpellCatalog`

データパックから魔法定義を読み込む。各エントリは以下を持つ。

- 魔法 ID
- 抽選ウェイト
- 最低特性ランク
- 安全分類
- 対象方式
- 任意の射程上書き
- 有効・無効

初期データでは、任意の一般 Mob が使用しても安全と確認できた Iron's Spells の魔法を広く登録する。アドオン魔法も ID で追加できる。不明な魔法 ID は起動エラーにせず、一度だけ警告して無視する。

### 6.5 `AllegianceResolver`

攻撃・支援の対象判定を一元管理する。

優先順位:

1. 明示的なスコアボードチーム
2. 所有者および召喚関係
3. Mob の現在の標的関係
4. 敵対 Mob / プレイヤー側エンティティの分類

攻撃魔法、投射物、範囲ダメージ、デバフは同陣営へ作用させない。回復・バフは自分および周囲の同陣営 Mob へ作用でき、プレイヤーまたはプレイヤー側 Mob へは作用させない。

## 7. 魔法 AI

初期の判断間隔は10 Tickとする。毎 Tick の広域探索は行わず、詠唱開始候補を探すときだけ制限範囲内を検索する。

各魔法に状況スコアを与える。

- 攻撃: 対象との距離、射線、範囲、クールタイム
- 回復: 自分または味方の欠損体力
- バフ: 同一効果を持たない有効対象数
- 防御: 直近の被ダメージ、現在体力
- 移動: 対象との距離および経路状況

使用可能な魔法のスコアへ設定可能なランダム補正を加え、最高スコアを選ぶ。最低実行スコアを満たさない場合は詠唱しない。ロードアウトの構成自体は役割保証を行わない。

## 8. 詠唱と中断

- 詠唱開始時に魔法系統へ対応した音とパーティクルを表示する。
- 詠唱中は対象へ視線を向け、移動速度を低下させる。
- 1回の実ダメージが最大体力の5%以上の場合、詠唱を中断する。
- 毒、炎などの小さな継続ダメージだけでは容易に封殺されない。
- 中断時は予定マナコストの25%を消費し、20 Tickの共通クールタイムを与える。
- 中断閾値、消費率、共通クールタイム、移動速度倍率はサーバー config で変更できる。
- 発動成功時は通常のマナコストを消費し、魔法固有クールタイムへ Mob レベル倍率を適用する。

## 9. 設定

### 9.1 サーバー config

少なくとも以下を提供する。

- MOD 全体の有効化
- Mob レベル基準値
- 強化段階幅
- 威力、マナ、回復、詠唱速度、クールタイムの段階係数
- 詠唱速度上限
- クールタイム下限
- AI 判断間隔
- ランダムスコア補正
- 詠唱中断の有効化
- 中断ダメージ閾値
- 中断時マナ消費率
- 中断後共通クールタイム
- 同士討ち防止の有効化
- 魔法 ID の追加許可リストおよび強制禁止リスト

### 9.2 L2 Hostility データパック

特性の `min_level`、`cost`、`weight`、`max_rank` を定義する。

### 9.3 Enemy Spell Cast データパック

魔法候補と AI 用メタデータを JSON で定義する。サーバーの `/reload` で再読込可能にする。ロードアウト済み Mob は、無効になった魔法だけを差し替える。

### 9.4 Entity Type タグ

- 自然付与対象外
- 支援対象外
- 強制的に魔法 AI を許可

のタグを提供する。初期除外にはボス、召喚 Mob、Iron's Spells 既存魔法 Mobを含める。

## 10. 表示とローカライズ

- 英語名: `Spell Caster`
- 日本語名: `魔導`
- L2 Hostility の特性表示へランク付きで表示する。
- 特性アイコンは魔法陣またはルーンを主題とし、L2 Hostility の既存 UI で判別できるサイズとコントラストにする。
- 詠唱予告は専用モデルを要求せず、サーバー同期される音、視線、パーティクルで表現する。

## 11. エラー処理と互換性

- 不明な魔法 ID は警告して無視する。
- 候補が空の場合、特性は維持するが魔法 AI を休止する。
- 保存データが破損している場合は、安全な初期値へ復旧してロードアウトを再生成する。
- 魔法発動中に対象が死亡、ディメンション移動、または無効化された場合は詠唱を中断する。
- Mob がアンロードまたは死亡した場合は一時状態を破棄する。
- クライアントは意思決定を行わず、サーバーを正とする。
- Iron's Spells の公開 API を優先し、非公開実装への依存は必要最小限に隔離する。
- 他 MOD Mobへの `IMagicEntity` 一括 Mixin は使用しない。

## 12. テスト戦略

### 12.1 単体テスト

- Mob レベルから強化段階を求める計算
- 威力、マナ、回復、詠唱速度、クールタイム計算
- 特性ランクから魔法レベルを求める計算
- レアリティフィルタ
- 重複なし加重抽選
- 敵味方判定の純粋ロジック
- 無効設定値の補正

### 12.2 GameTest / 統合テスト

- 特性付与による Goal 起動
- ランク別魔法数
- 保存および再読込後のロードアウト維持
- 詠唱成功とマナ消費
- ダメージによる中断
- マナ不足とクールタイム中の通常 AI 継続
- 攻撃魔法の同士討ち防止
- 回復・バフの味方適用
- 除外 Entity Type の扱い

### 12.3 実環境確認

- NeoForgeクライアント起動
- 専用サーバー起動
- L2 Hostility 3.0.18 および Iron's Spells 3.16 系とのロード
- 複数種のバニラ敵対 Mob と他 MOD Mobでの詠唱
- 多数の特性 Mob が存在する状況での Tick 負荷

## 13. 受け入れ条件

1. レベル100以上の対象 Mob に、L2 Hostility 標準抽選で本特性が付与される。
2. 特性ランクに応じて1、1、2、2、3種類の重複しない魔法を保持する。
3. ランク5では、候補となった魔法の本来の最大レベルを使用する。
4. Mob レベルに応じ、合意した段階式で性能が強化される。
5. 詠唱は視覚・聴覚で予告され、設定したダメージで中断できる。
6. 攻撃魔法は同陣営 Mob に作用せず、回復・バフは同陣営 Mob に作用する。
7. ロードアウトは保存・再読込後も維持される。
8. 魔法を使えない状況では通常攻撃 AI が機能する。
9. config、データパック、タグの不正値でサーバー全体がクラッシュしない。
10. クライアントと専用サーバーの双方で起動し、必須 MOD がない場合は依存関係エラーを明確に表示する。
