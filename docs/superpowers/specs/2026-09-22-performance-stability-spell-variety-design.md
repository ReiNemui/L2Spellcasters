# Enemy Spell Cast 軽量化・安定化・魔法拡張 設計仕様

## 1. 背景

Enemy Spell Cast 0.1.0 は、L2 Hostility の `Spell Caster` / `魔導` 特性を持つ敵が Iron's Spells 'n Spellbooks の魔法を使用するところまで動作確認済みである。自然出現ウェイトは L2 Hostility の一般的な特性と同程度の `100` に調整済みで、実機でも特性表示と魔法発動を確認できている。

次の改修では、多数の敵が同時に出現する MOD パックでの負荷を抑え、特性解除などで残る可能性がある状態を確実に片付ける。同時に、実機テストで不足が感じられた魔法バリエーションを、安全性を維持しながら増やす。

## 2. 目標

1. 多数の `Spell Caster` Mob が存在しても、変化のない状態で毎 Tick 行う処理と一時オブジェクト生成を最小化する。
2. 特性解除、MOD 無効化、データパック再読込、Entity 離脱時に AI、詠唱、能力補正、一時状態を確実に更新または破棄する。
3. 攻撃、範囲攻撃、拘束、移動、回避、回復、強化を含む、およそ45～55種の安全な魔法候補を初期データへ収録する。
4. 既存の成長式、判断間隔、ランダム性、ロードアウト保存形式、マナ、詠唱中断、クールタイムの体感は原則として維持する。
5. 将来の Iron's Spells 更新や候補追加に対し、個別の互換処理を小さなアダプターとして追加できる構造にする。
6. サーバー config から、敵が使用できる魔法を追加、禁止、または許可リストだけに限定できるようにする。

## 3. 非目標

- L2 Hostility の特性抽選方式やランク算出方式の変更
- 既存 Mob の通常攻撃 AI の置換
- Mob を生成する召喚魔法の標準候補への追加
- 地形破壊、採掘、ポータル、ディメンション移動、帰還処理を行う魔法の標準候補への追加
- プレイヤー専用 UI や手動照準を前提とする魔法の追加
- 判断間隔を延ばすことで見かけ上の負荷を下げる調整
- 非公開実装へ広範囲に依存する汎用的な魔法互換レイヤー

## 4. 互換性優先の方針

軽量化によって、同じ入力から得られる戦闘結果を意図的に変更しない。以下は現行値と現行ロジックを維持する。

- AI の判断間隔
- 状況スコアとランダム補正の計算順序
- 特性ランクごとの魔法スロット数
- L2 Mob レベルによる威力、マナ、詠唱速度、クールタイムの成長式
- ロードアウトの永続化と、無効になったスロットだけを補充する挙動
- ダメージによる詠唱中断条件
- 攻撃魔法の同士討ち防止と、味方への回復・強化

キャッシュは計算結果の再利用だけに用い、乱数抽選を省略、先送り、追加しない。魔法候補の拡張によって新しく生成される個体のロードアウト分布は変化するが、既存 Mob の有効な保存済みロードアウトは維持する。

## 5. ホットパスの軽量化

### 5.1 Config スナップショット

現状は特性 Tick から設定値を取得するたびに、新しい設定レコードとリストを構築する。これを、読取専用の不変スナップショット1個へ変更する。

- 起動時および NeoForge の config load/reload イベントでだけスナップショットを構築する。
- Tick と AI は現在のスナップショット参照を取得するだけにする。
- スナップショットには単調増加する `configGeneration` を持たせる。
- 強制許可・禁止 ID は構築時に検証済みの不変集合へ変換する。
- 不正値の補正と警告はスナップショット構築時に一度だけ行う。

これにより、Mob 数に比例して毎 Tick 発生していた設定オブジェクトとリストの割り当てをなくす。

### 5.2 使用可能魔法の config 制御

初期設定は、同梱データパックの候補をそのまま使う `default_pool` モードとする。既存の `forceAllowSpellIds` と `forceDenySpellIds` を維持し、さらに候補を完全指定できる選択モードを追加する。

想定する設定:

- `spellOverrides.selectionMode = "default_pool"`
  - `default_pool`: 同梱および追加データパックの候補を基準にする。
  - `allowlist_only`: `allowedSpellIds` に記載された魔法だけを候補にする。
- `spellOverrides.allowedSpellIds = []`
  - `allowlist_only` の候補一覧。空の場合は安全のため候補なしとして扱う。
- `spellOverrides.forceAllowSpellIds = []`
  - `default_pool` へ安全確認済みの魔法 ID を追加する。
- `spellOverrides.forceDenySpellIds = []`
  - すべてのモードで候補から除外し、他の指定より優先する。
- `behavior.excludeSummoningSpells = true`
  - Mob や長命な疑似 Mob を生成する魔法を除外する。
- `behavior.excludeTerrainChangingSpells = true`
  - ブロックの破壊、採掘、設置など地形を変更する魔法を除外する。
- `behavior.excludePortalSpells = true`
  - ポータル、ディメンション移動、帰還地点を扱う魔法を除外する。

優先順位は `forceDeny > 有効なカテゴリ除外 > 明示許可 > selectionMode の通常候補` とする。`forceAllow` は `default_pool` モードだけに適用し、`allowlist_only` の「記載魔法だけ」という意味を崩さない。

config は使用可否を簡単に変更する入口とし、ウェイト、最低特性ランク、対象方式、射程などの詳細調整は従来どおり spell pool JSON で行う。config から追加された魔法にも、登録済み spell pool 定義が必要である。

召喚、地形変更、ポータル系は標準候補へ含めず、対応する `exclude...Spells` の既定値をすべて `true` とする。危険カテゴリの魔法を実行可能にするには、管理者が次の両方を満たす必要がある。

1. 対応する除外設定を `false` にする。
2. `default_pool` では `forceAllowSpellIds`、`allowlist_only` では `allowedSpellIds` へ、その魔法 ID を明示的に記載する。

除外設定を `false` にしただけでは危険カテゴリを自動追加しない。許可リストへ記載しただけでも、対応する除外設定が `true` なら実行しない。これらは非推奨・無保証の実験機能とし、同士討ち、召喚物の所有関係、地形復旧、チャンク境界、ディメンション移動先、他 MOD との競合について正式サポート対象外とする。「実行可能」は本 MOD 側のカテゴリ除外を解除することを意味し、Iron's Spells 側がプレイヤー専用条件などで拒否する魔法の動作までは保証しない。

ただし、存在しない魔法 ID、読み込めない定義、登録されていない Behavior、呼出前に明確に検出できる不正状態は引き続き拒否し、サーバー全体の起動を妨げない。実験機能が有効な場合は、config 読込時に一度だけ警告を出す。

設定再読込時は `configGeneration` と有効カタログを更新する。既存 Mob は、引き続き許可されている保存済み魔法を保持し、禁止または対象外になったスロットだけを新しい候補から補充する。候補が空なら特性を維持したまま魔法 AI を休止し、エラーを繰り返し出力しない。

### 5.3 Mob ごとの導入状態

`SpellGoalInstaller` は Mob ごとに、最後に適用した状態を保持する。

保存する一時情報:

- 特性ランク
- L2 Mob レベル
- `configGeneration`
- `catalogGeneration`
- 算出済みスケーリング値
- Goal と Controller が導入済みか

特性 Tick の入口で上記キーを比較し、すべて同一なら即座に終了する。この早期終了ではロードアウト抽選、スケーリング再計算、Controller 更新、属性補正の付け直しを行わない。

ランク、Mob レベル、設定、カタログのいずれかが変化した場合だけ、必要な部分を更新する。Goal の多重登録は引き続き禁止する。

### 5.4 魔法威力属性

魔法威力の属性 Modifier は、望ましい値が現在値と異なる場合だけ差し替える。

- 浮動小数点比較には小さな許容誤差を設ける。
- Modifier ID は固定し、同じ効果が重複しないようにする。
- 特性解除、対象外化、MOD 無効化、Entity 離脱時は Modifier を明示的に削除する。

### 5.5 SpellCatalog の事前計算

データパック再読込の完了時に、次を一度だけ作成する。

- 魔法 ID から候補定義を引く不変 Map
- 特性ランク1～5それぞれの抽選可能候補リスト
- 有効候補の全体リスト
- `catalogGeneration`

ロードアウト生成や AI 判断中に毎回リストを走査してランク条件を絞り込まない。再読込に失敗した場合は、妥当性が確認できた直前のカタログを維持し、候補全体を空にしない。

### 5.6 状況判断時の検索共有

1回の AI 判断中に、味方候補の周辺検索を最大1回だけ行う。回復魔法と強化魔法は同じ候補一覧を使い、それぞれの条件で採点する。

- 周辺検索結果を Tick をまたいで保持しない。
- 敵対象は Mob の現在の攻撃対象を基本とし、不要な全 Entity 探索を追加しない。
- 一時 Map を必須とせず、候補を順に採点しながら最良値を保持する。
- 同点処理とランダム補正の回数・順序は現行挙動を維持する。

## 6. ライフサイクルと不具合修正

### 6.1 特性ランク0・対象外化

特性ランクが0になった、対象 Entity タグや config によって対象外になった、または全体設定が無効になった場合は、休止だけでなく明示的な解除処理を行う。

解除対象:

- `SpellCasterGoal`
- `SpellCastController`
- 進行中の詠唱
- 魔法威力 Modifier
- Mob ごとの導入状態
- 実行時レジストリの一時データ

永続ロードアウトは特性の再付与に備えて Mob データへ残してよい。ただし、解除中にマナ回復、クールタイム更新、詠唱判断は行わない。

### 6.2 MOD 無効化と再読込

config の `general.enabled` が `false` へ変化した場合、進行中の詠唱を中断し、新規詠唱を禁止する。単に次の `canUse` 呼び出しを待つのではなく、Controller 更新経路または config 再読込時の世代変化を通じて確実に停止させる。

再び有効化した場合は、次の特性 Tick で通常どおり再導入する。無効化による中断では、戦闘上の中断ペナルティを与えない。

### 6.3 Entity 離脱

Entity の死亡、アンロード、ディメンション離脱では、実行時レジストリと導入状態から明示的に削除する。弱参照 Map は保険として残せるが、値から Mob への強参照があることを前提に、明示的な後始末を正とする。

### 6.4 支援魔法の caster と target

味方へ回復・強化を行うアダプターでは、次を分離する。

- AI の所有者、消費マナ、クールタイムを管理する caster は特性 Mob
- 魔法効果を受ける target は選択された味方 Mob
- Iron's Spells が自己詠唱として実行する場合の execution entity と `MagicData` は target

Iron's Spells の API が自己詠唱しか受け付けない魔法は、実装ごとに所有権、`MagicData`、効果対象を確認する。対象を execution entity としながら元 caster の `MagicData` を渡すような組合せは使用しない。自己詠唱型では効果量が target 側の属性を参照する可能性を許容し、本 MOD の Mob レベルによる魔法威力補正は攻撃 caster に対する保証とする。安全な適用方法を確認できない魔法は候補へ入れない。

### 6.5 対象データを必要とする魔法

`root`、`slow` など、詠唱前に `TargetEntityCastData` を要求する魔法には専用の `target_entity` Behavior を追加する。

- AI が選んだ対象を直接 CastData に設定する。
- Mob の見ている方向に依存する再レイキャストだけで対象を決めない。
- 対象の死亡、無効化、射程外、別ディメンション移動時は安全に失敗または中断する。
- 専用 Behavior は登録式にし、将来同種の魔法をデータ定義から追加できるようにする。

### 6.6 同士討ち防止

既存の `SpellDamageEvent` による保護を維持し、追加する範囲攻撃・拘束・デバフについて、ダメージ以外の有害効果も味方へ入らないことを確認する。

Iron's Spells がキャンセル可能な効果イベントを提供する場合は、`AllegianceResolver` を共通判定として利用する。イベントで安全に防げない魔法は、専用アダプターで対象を絞るか標準候補から除外する。見た目上味方へ当たっても実害がないことを GameTest で確認できない魔法は収録しない。

## 7. 魔法候補の拡張

### 7.1 規模と構成

初期候補を現在の28種から、およそ45～55種へ拡張する。3スロットすべては従来どおり同一候補集合から重複なしで抽選し、攻撃・支援などの役割固定は行わない。

候補カテゴリ:

- 単体投射・直線攻撃
- 範囲・連鎖攻撃
- 拘束・減速・引き寄せ・吹き飛ばし
- テレポート・回避・位置調整
- 回復・防御・強化
- 短時間だけ存在する牙、結界、弾体などの非 Mob 魔法 Entity

初期追加候補には、実装調査と統合テストを通過することを条件に、次を含める。

- 移動: `teleport`, `blood_step`, `evasion`
- 拘束・操作: `slow`, `root`, `arcane_shackle`
- 範囲・連鎖: `chain_lightning`, `arrow_volley`, `firecracker`, `ice_spikes`, `shockwave`, `ball_lightning`, `gravity_fissure`
- 一時設置物: `fang_ward`

名称は Iron's Spells 1.21.1-3.16 系の登録 ID と照合して確定する。候補数を満たすための追加魔法も、同じ安全基準で個別に評価する。

### 7.2 抽選ウェイト

極端に出にくい魔法は作らない一方、強力な範囲攻撃や継続設置物がロードアウトを占有しすぎないようにする。

| 種別 | 標準ウェイト | 解禁ランクの目安 |
| --- | ---: | ---: |
| 基本的な単体投射 | 10 | 1 |
| 範囲・連鎖攻撃 | 7～8 | 2以上 |
| 拘束・引き寄せ・吹き飛ばし | 7～8 | 2以上 |
| テレポート・回避・移動 | 7 | 1～2以上 |
| 強力または持続する範囲 | 5～6 | 3以上 |
| 回復・防御・強化 | 6～8 | 効果に応じて1～3以上 |

各候補の最終ランクは、魔法本来のレアリティ、危険度、射程、範囲、持続時間を合わせて決める。特性ランク5では候補魔法の本来の最大魔法レベルを使用する既存仕様を維持する。

### 7.3 標準候補から除外するもの

- Zombie、Vex、Polar Bear、Horse、Creeper など Mob を生成する召喚魔法
- 長時間追従する剣など、実質的に召喚 Mob に近い魔法 Entity
- ブロック破壊、採掘、設置、地形変更を行う魔法
- ポータル、ディメンション移動、帰還地点を扱う魔法
- プレイヤーの画面、キー入力、インベントリ操作を前提とする魔法
- 任意 Mob caster で安全性を確認できない継続詠唱魔法
- 敵味方を区別せず有害な状態効果を直接付与し、発生源付きイベントで防げない魔法
- 所有者や寿命の後始末を保証できない魔法 Entity

短命な非 Mob Entity は、寿命、所有者、チャンクアンロード、同士討ちを確認できたものだけ標準候補へ収録する。

本節のうち召喚、地形変更、ポータル系は、5.2節の二重オプトインを満たした場合だけ実験的に実行を許可できる。それ以外のプレイヤー UI 前提、未登録 Behavior、ロード不能な魔法は、除外設定にかかわらず実行しない。

## 8. データ形式と拡張性

既存の spell pool JSON 形式を維持し、必要な場合だけ `behavior` に新しい値を追加する。

想定 Behavior:

- `direct`: 通常の敵対象または自己対象
- `ally_self_cast`: 安全確認済みの味方対象型回復・強化
- `target_entity`: 選択済み対象を `TargetEntityCastData` へ設定
- 必要になった魔法だけに限定した専用 Behavior

未知の Behavior や存在しない魔法 ID は、そのエントリだけを警告して無効化する。カタログ全体の再読込やサーバー起動は継続する。

既存 Mob の保存データ形式は変更しないことを優先する。変更が必要な場合はデータバージョンを上げ、旧ロードアウトの魔法 ID を可能な限り保持する移行処理を追加する。

## 9. 検証戦略

### 9.1 単体テスト

- config を変更しない複数回参照で同一スナップショットが返る
- config reload で世代が増え、新しい値が反映される
- `default_pool` では初期候補が変わらず、強制許可・禁止だけが反映される
- `allowlist_only` では記載された安全な魔法だけが候補になり、禁止リストが優先される
- 許可リストが空、未知 ID、危険な魔法 ID を含む場合もクラッシュしない
- 召喚、地形変更、ポータル系は、対応する除外設定が `true` なら明示許可されていても除外される
- 危険カテゴリは、対応する除外設定が `false` かつモードに合う許可リストへ明示記載された場合だけ候補になる
- 危険カテゴリの除外を解除すると警告が一度だけ出る
- カタログ再読込でランク別候補と ID Map が一度だけ再構築される
- 同じ Mob 状態で installer の重い更新処理が繰り返されない
- レベル、ランク、config 世代、catalog 世代の変化時だけ再計算される
- 同一威力では属性 Modifier を付け直さない
- 1回の判断で味方周辺検索が1回以下になる
- `target_entity` が AI の選択対象を CastData へ設定する
- 候補の ID、ウェイト、最低ランク、Behavior が妥当である

実時間だけを測る不安定なベンチマークは合否判定に使用しない。代わりに、50体相当を複数 Tick 更新した際の設定再構築、スケーリング再計算、Modifier 更新、周辺検索の呼出回数を計測し、変化のない状態で Mob 数×Tick 数に比例して重処理が増えないことを決定的に検証する。

### 9.2 GameTest

- 攻撃魔法が敵対対象へ実際に発動する
- `root` または `slow` が選択したプレイヤーへ適用される
- 回復・強化が負傷した味方へ適用され、caster のマナとクールタイムが正しく更新される
- テレポート系が安全な位置へ移動し、ブロック内や奈落へ移動しない
- 範囲攻撃と拘束が同陣営 Mob にダメージ・有害効果を与えない
- 特性解除直後に Goal、Controller、Modifier、詠唱が消える
- config 無効化中に進行中の詠唱が無償で停止する
- Entity 離脱後に実行時状態が残らない
- `/reload` 後も有効な保存済みロードアウトが維持され、無効スロットだけ補充される

### 9.3 回帰確認

- 既存 JUnit テストをすべて通す
- NeoForge GameTest をすべて通す
- clean build を通す
- 実機で複数種類の敵へ特性を付与し、魔法の偏り、詠唱中断、通常 AI への復帰を確認する
- 多数の特性 Mob がいる試験環境で、エラーログと明らかな Tick 停滞がないことを確認する

## 10. 受け入れ条件

1. 変化のない特性 Mob の毎 Tick 処理で、config の再構築、スケーリング再計算、属性 Modifier の再付与を行わない。
2. 味方検索は1回の AI 判断につき最大1回で、判断結果の意味を変えない。
3. 特性解除またはMOD無効化後、魔法 AI、進行中の詠唱、能力補正が残留しない。
4. カタログ再読込後、ランク別キャッシュが更新され、既存の有効ロードアウトを不要に再抽選しない。
5. 初期魔法候補が45～55種程度になり、攻撃以外に拘束、テレポート、回避、回復、強化を含む。
6. Mob 召喚、長命な疑似召喚、地形破壊、ポータル系は標準候補に含まれず、既定 config では実行できない。
7. 追加した範囲攻撃・拘束・一時 Entity が同陣営へ実害を与えない。
8. 対象データ型魔法が Mob の視線偶然ではなく、AI が選んだ対象へ作用する。
9. 既存の成長式、スロット数、詠唱中断、判断間隔、保存済みロードアウト互換性を維持する。
10. 初期 config では同梱候補をそのまま使用し、`allowlist_only` では管理者が指定した安全な魔法だけを敵が使用する。
11. config 変更後、許可された既存スロットは維持され、禁止されたスロットだけが差し替わる。
12. 召喚、地形変更、ポータル系は、カテゴリ除外の解除と魔法 ID の明示許可を両方行った場合だけ、非推奨・無保証で実行可能になる。
13. 全 JUnit、GameTest、clean build が成功する。

## 11. 実装順序

1. 現在の挙動を固定する回帰テストと、残留状態・重複更新を再現する失敗テストを追加する。
2. config スナップショットと世代管理を導入する。
3. Mob ごとの導入状態と属性 Modifier の差分更新を導入する。
4. 特性解除、無効化、Entity 離脱の後始末を統一する。
5. SpellCatalog のランク別キャッシュと世代管理を導入する。
6. 状況判断内の味方検索を共有する。
7. `target_entity` と支援魔法アダプターをテスト駆動で整備する。
8. 魔法候補をカテゴリごとに少量ずつ追加し、統合テストを通過した候補だけ残す。
9. 全体テスト、clean build、実機用チェックリストを更新する。

各段階は個別に戻せる小さな変更として進める。軽量化、ライフサイクル修正、魔法追加を同じ大規模変更へ混在させず、失敗時に原因を切り分けられるようにする。
